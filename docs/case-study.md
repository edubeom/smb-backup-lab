# dev-process-light 실제 적용 기록

## 작업 카드
매일 한 번, 검증 성공 한국 날짜5개 보관, 프로젝트별 암호화 파일, SSH/터널/DB/메일 포함, 서비스 유지, 키/비밀은 Git 밖, 별도 복구 시험이라는 기준을 기록했다.

## 재현한 문제와 수정
1. SMB 오류22를 반복 암호 입력으로 해결하지 못했다. 협상 결과를 조사해 이 공유기의 버전 설정을 맞췄고 오류13/22를 구분했다.
2. “메일 중단 없이”라는 요구에 맞춰 서비스 제어 경로를 제거하고 Dovecot/SQLite/Redis 온라인 수집으로 바꿨다. 전체 공통 시점은 보장하지 않고 SMTP 큐 검사 실패 시 기존 성공본을 보존한다.
3. 첫 설정의 archive_layout 누락을 백업기는 기본값으로 처리했지만 설치기는 거부했다. 보존한 과거 설정으로 재현해 기본값 처리를 맞췄다. 공개본에는 필요한 예제를 tests/fixtures/legacy-backup.example.json으로 제공한다.
4. 긴 승인 입력에 대한 의견을 받아 y/Enter로 줄였다. 이미 저장한 canonical 승인 정책은 유지해 매일 실행이 막히지 않게 시험했다.

## 확인 범위
123개 합성 시험과 실제 사례 실행을 구분한다. 사례에서는 첫 암호화 성공본2.819GiB, PG5개 격리 복원/읽기, 메일SQLite와 우편함7개 읽기, 외부 키 재입력/공유기 명세 복호화, 일일 예약 활성까지 확인했다. 제작 기준2026-10-20에 첫 예약 성공/재부팅 연결/전체 Mailu 로그인·송수신/앱·보존 볼륨 전체 복구는 아직 미검증이다.

## 공개 자료
서버 조사 원문·실제 호스트/사설 주소/운영자명/프로젝트 식별자·원본 Git 이력·과거 source 사본은 제외하거나 예시로 바꿨다. PNG는 그때 제작한 공개 진행 카드이며 실제 서버 화면 녹화가 아니다. 값 없는 요약 수치는 유지했다.
