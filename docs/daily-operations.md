## 개인 G1 터미널에서 적용

```bash
sudo python3 /project/smb-backup-lab/scripts/enable_daily.py --apply
```

실제 공유·저장소 표식·공간·기존 PostgreSQL/외부 키 검증 receipt와 systemd 충돌을 확인한 뒤 계획을 표시한다. **위 반복 정리에 동의할 때만 `y`를 입력한다.** Enter/n은 취소다. 긴 문장을 다시 입력할 필요가 없도록 변경했다. 이전 긴 문구로 저장한 승인 기록은 그대로 유효하며 보호 파일의 정책/범위를 변경하지 않는다. 취소하면 설치·승인 저장·timer 시작을 하지 않는다. 비밀번호나 키는 다시 묻지 않는다. 필요하면 `--apply` 대신 `--inspect`로 읽기 전용 점검만 할 수 있다.

확인을 요구하는 이유는 사용자의 “기존 백업 삭제 전에는 확인받기” 조건이다. 승인 범위를 root 전용 `/etc/g1-backup/operations.json`에 저장하고 저장소 경로·표식·호스트를 매번 대조한다. 이 파일이 없으면 자동 정리는 동작하지 않는다. 실제 비밀은 이 승인 기록에 넣지 않는다.

기존 systemd/fstab 설정이 충돌하면 덮어쓰지 않는다. 적용 중 systemctl 오류가 나면 파일만 일부 설치됐을 수 있으므로 마지막 오류 JSON을 알려 주고 상태를 확인한다. 자동 되돌리기나 공유 해제는 하지 않는다.

성공은 `status=daily-backup-enabled`, `timer_enabled=enabled`, `timer_active=active`와 다음 실행 시각으로 판단한다. **설치 성공과 첫 예약 백업 성공은 별도다.** timer의 놓친 실행 보충 때문에 설치 후 백업이 시작될 수 있으나 이미 성공한 한국 날짜에는 수집하지 않는다. 재부팅 복구 시험은 서비스 중단을 수반할 수 있어 이번 설치에서 재부팅하지 않는다.

## 상태 확인

```bash
sudo python3 /project/smb-backup-lab/scripts/status.py
systemctl list-timers g1-backup.timer --all
sudo journalctl -u g1-backup.service -n 30 --no-pager
```

첫 명령은 키나 데이터 내용을 출력하지 않는다. 마지막 성공, 일일 작업의 시작/종료/실패, 이전 실패 이력, 마지막 정리와 설치 당시 상태를 구분한다. `last_daily_failure`는 다음 성공 뒤에도 과거 실패 이력으로 남으므로 그 시각과 `daily`를 함께 본다. `running` 상태로 오래 남으면 프로세스 강제 종료/호스트 종료 가능성을 journal과 service 상태로 확인한다. 마운트 실패로 service 자체가 시작되지 못하면 Python 상태 파일은 갱신되지 않을 수 있으므로 systemd 상태도 확인한다. **journal 원문 전체는 촬영/채팅에 붙이지 말고 마지막 안전한 JSON과 오류 종류만 공유한다.**

## 정리 실패와 남은 평문

정리 전에는 보존할 성공본과 삭제 후보 모두의 암호화 파일 해시·정확한 파일 목록을 검사한다. 손상·symlink·모르는 파일이면 삭제 전에 거부한다. 삭제 중 단절되면 해당 성공 선언을 먼저 제외했으므로 불완전한 파일을 성공본으로 세지 않는다. 남은 orphan/partial은 자동 재삭제하지 않고 용량에 포함해 멈추며, 후속 조사와 별도 확인 후 처리한다. 새 백업은 검증을 마쳤어도 정리 실패로 daily가 실패할 수 있으며 이때 `last-success.json`과 daily 실패를 구분한다.

이전 수집/복원본과 실패한 수집본은 자동 삭제하지 않는다. 기존 root 공간 53.12GiB는 PostgreSQL 시험 당시 측정치이며 설치 전 다시 검사한다. 이후 누적은 상태·공간으로 살피고 삭제할 구체적 경로/크기를 제시해 따로 확인받는다. 일일 작업의 새 성공 수집본은 승인된 범위에서 정리해 반복 누적을 막는다. 백업은 매일 독립 묶음이며 향후 데이터 증가·실패 조각 때문에 50GiB에 도달하면 상한/대상을 재검토한다.

설계 근거: systemd 공식 [mount 단위와 기존 마운트 추적](https://www.freedesktop.org/software/systemd/man/latest/systemd.mount.html), [timer와 Persistent](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html). 설치 서버의 `systemd-analyze verify`와 한국 시간 캘린더 해석도 직접 확인했다. 실제 부팅 연결·첫 예약 실행은 설치 후 확인 항목이다.

## 초기 설정에서 설치 검사가 막혔을 때

2026-10-20 사용자 실행이 “설치 도구는 조사한 G1 경로·SMB 2.0·objects-v2 설정만 지원합니다”로 중단됐다. 당시 최초 setup 설정에는 `archive_layout` 항목이 없고 백업 실행기는 이를 objects-v2로 해석했지만 설치기는 명시 항목만 인정하는 오류가 있었다. 보존한10단계 설정으로 재현해 설치기도 같은 기본값을 적용하도록 수정했다. 보호된 실제 설정 파일은 변경하지 않았으며 설정을 다시 만들거나 암호를 재입력할 필요가 없다.

수정 후 위의 동일한 `--apply` 명령을 다시 실행한다. 명시적으로 다른 형식/경로/SMB 버전을 설정한 경우는 계속 거부한다. 다른 불일치가 있으면 비밀 값을 출력하지 않고 항목 이름만 표시한다. 오류 JSON의 `phase`와 `installation_started=false`이면 승인 기록·설치 단위 파일 저장·timer 시작 전 중단이다. true일 때에는 일부 설정이 적용됐을 수 있어 상태 확인 후 이어간다. 이번에 보고된 오류는 첫 `unit_texts` 검사에서 발생했으므로 해당 시도는 설치를 시작하지 않았다.
