# 첫 공유기 성공본의 PostgreSQL 복구 결과

사용자가 관리자 터미널에서 verify_postgres.py를 실행한 마지막 JSON을 제공했다. 시험 시각은 **2026-10-20 14:49:43 Asia/Seoul**, 성공 ID는 `20261020T040000000000-1234abcd`다. 에이전트가 root 전용 명세나 비밀을 직접 읽은 결과와 구분한다.

## 확인 결과

- `status=shared-snapshot-postgresql-restore-verified`
- 공유기 성공본의 암호화 파일 전체 해시 재검사와 선택 복호화 통과.
- globals/원래 역할과 **5개 DB 전체**를 새 PostgreSQL에 복원·실제 테이블 읽기 완료.
- 5개 DB 모두 invalid_indexes=0. 역할·소유권·ACL을 생략하지 않고 복원 요청했으며 오류 중단 옵션으로 완료.
- 네트워크 none, 공개 포트/host bind 없음, 운영 볼륨 재사용 없음.
- 시험 컨테이너 회수 후 기존 컨테이너 상태(시작 시각·재시작 횟수 등) 불변.
- 운영 서비스 중단·기존 백업 삭제·timer 활성화 없음.

원본 백업 당시 행 수/해시 기준은 없으므로 복원한 행 수를 원본과 대조했다고 주장하지 않는다. 애플리케이션 로그인/업무 조회와 Mailu 전체 로그인·부가 서비스 복구도 이번 결과에 포함되지 않는다. 상세 비공개 결과는 `/var/lib/g1-backup/work/verify-pg-20261020T040000000000-1234abcd-3f8728fb/result.json`에 있다.

## 실제 공간 측정

| 항목 | 결과 |
|---|---:|
| 이번 암호화 백업 구성요소 합계 | 3,026,556,349 bytes / 2.819GiB |
| metadata 등을 포함한 저장소 사용량 | 3,026,569,593 bytes |
| 같은 크기 성공본 5개 | 약 14.094GiB |
| 새 백업 검증 후 정리 전 6개 | 약 16.912GiB |
| 사용자 G1 상한 | 50GiB |
| 검사 당시 공유 저장소 여유 | 약 973.601GiB |
| 검사 당시 G1 로컬 여유 | 약 53.120GiB |

현재 크기에서는 5개와 추가 시점의 6개 모두 상한 안에 들어간다. 미래 데이터 증가·실패 partial·로컬 평문 누적과 공용 디스크의 다른 프로그램 사용량을 계속 감시한다. 이 계산은 기존 백업 삭제 승인이 아니며 자동 정리는 아직 비활성화다.
