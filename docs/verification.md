# 1차 개발 확인 결과

최신 상태: 첫 전체 공유기 백업·선택 설정 파일/메일 DB·7개 격리 우편함 읽기는 사용자 결과로 확인했다. 현재 합성 안전장치 시험은 93개이며 공유기 성공본의 PostgreSQL 5개 실제 복원·읽기도 사용자 결과로 확인했다. 키 외부 보관·Mailu 전체/앱 복구·자동 실행은 남아 있다. 아래는 단계별 당시 확인과 후속 결과를 보존한 기록이다.

2026-10-20, G1 프로젝트에서 실행. 운영 서비스는 중단하지 않았다.

## 직접 확인

- `python3 -m unittest discover -s tests -v`: 72 tests, 모두 통과. Python 표준 unittest 사용.
- GnuPG로 가상 파일을 실제 암호화하고 가상 저장소로 복사한 뒤 읽기·복호화·압축 해제·파일 해시 비교 통과.
- 미마운트/잘못된 mount 출처, 호스트/저장소 ID 오류, 키 권한/symlink, 동시 실행, 같은 날 재시도, stale prepared 자료, 실패본 제외, 한국 날짜 기준 성공 5일 후보, 공간 부족, 압축 경로 탈출·중복·손상·덮어쓰기 경계 시험.
- 일일 실행기의 당일 성공 후 재수집 방지·수집 실패 후 전송 미호출·새 staging 전달을 mock으로 확인.
- 설정 기본값 disabled, 자동 삭제 구현 없음. systemd 파일은 프로젝트 템플릿이며 서버에 설치하지 않음.

## 아직 확인하지 못한 것

- 지속적인 공유기 전송 안정성. SMB 2.0 rw 마운트와 사용자 상한 50GiB는 확인했지만 첫 전체 쓰기/읽기 검사는 root 실행 대기.
- `scripts/prepare.py` 실제 운영 수집. root 실행 필요. 중단 승인/서비스 제어 경로는 제거했고 전용 온라인 내보내기 사용.
- PostgreSQL/Mailu/Story.db/Qdrant를 별도 환경에서 실제로 시작하는 복구 시험.
- ACL/xattr/UID/GID와 inner tar 시스템 복구, 외부에서의 메일 송수신.
- 일일 실행기의 실제 운영 시험, mount 자동화, timer 설치, 실패 알림, 승인 후 보관 삭제.

따라서 이 상태는 **기반 도구 개발·가상 시험 통과**이며 운영 백업 구축 완료가 아니다. 개발용 가상 저장소는 SMB가 아닌 임시 로컬 디렉터리였고 SMB 검사 부분은 mock으로 검증했다.

## 자료와 화면 검증

설명서 17쪽 check/review 통과·육안 확인. 실제 브라우저에서 P/N 기능과 안내 링크 접근, page error 0 확인. 영상 64초 1080p H.264의 전체 디코딩 통과, 음성 없음. 여섯 단계 소스 해시 및 설치된 data-light 전체 고정 해시 일치.

## 공유 인증 재입력 수정

기존 코드가 실패한 인증 파일을 재사용해 비밀번호를 다시 묻지 않는 동작 확인. --reset-smb-password 추가, 기존 인증 실패 시 자동 재입력, 두 번 입력/최대 3회, 임시 0600 인증으로 연결 검사 후에만 원자적 교체. 실패·취소·입력 불일치 시 기존 파일 보존, 이미 연결 중이면 해제하지 않음, 오류 숫자 외 원문 비밀 출력 없음. 관련 7개 시험 추가하여 전체 40개 통과. 실제 사용자 공유 인증은 재입력 후 확인 필요.
