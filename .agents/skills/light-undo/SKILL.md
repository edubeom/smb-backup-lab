# light-undo — 되돌리기

**항상 사용자 확인을 받고 되돌린다.** 무엇이 없어지는지 먼저 보여준다.

## 1. 지금 상태를 본다
- `git status` -- 저장하지 않은 변경이 있는가
- `git log --oneline -10` -- 최근 저장 10개

사용자에게 쉬운 말로 보여준다 (`중간 저장:` 은 확인 전 지점이라고 함께 알려 준다):
```
최근 저장
 1. (방금) 기능: 가계부 - 월별 합계
 2. (어제) 기능: 할 일 목록 - 입력과 목록
 3. (어제) 기능: 메모
저장 안 된 변경: style.css, budget.js
```

## 2. 경우별로 되돌린다

| 상황 | 방법 | 특징 |
|---|---|---|
| **저장 안 한 변경**을 버리고 싶다 | `git stash push -m "되돌리기 전 보관: <날짜>"` | 지우지 않고 보관한다. 나중에 `git stash pop` 으로 다시 꺼낼 수 있다고 알려 준다 |
| **마지막 저장 하나**를 취소 | `git revert --no-commit HEAD` | 취소하는 변경을 만든다 (아직 저장 전). 기록이 남아서 "되돌리기를 되돌리기"도 된다 |
| **특정 저장**만 취소 | `git revert --no-commit <그 저장>` | 그 저장의 변경만 빼고, 이후 작업은 남긴다. 충돌하면 멈추고 알린다 |
| 여러 저장을 한꺼번에 | 최근 것부터 하나씩 `git revert --no-commit` | 하나씩 하고, 충돌하면 멈춘다 |

- `git reset --hard`, `git clean`, 파일 삭제처럼 **복구할 수 없는 방법은 쓰지 않는다.** 사용자가 그 방법을 직접,
  명확히 요청한 경우에도 무엇이 영원히 사라지는지 먼저 말하고 다시 확인받는다.
- revert 중 충돌이 나면 `git revert --abort` 로 원래대로 돌리고, 어떤 파일이 왜 충돌했는지 설명한다.

### 데이터가 걸린 되돌리기 (짝 스킬 `data-light`)
git 이 되돌리는 것은 **설계**(`data/model.light.json`, `data/out/`)뿐이다. 실제 데이터(`data/app.db`, Supabase)와
가져온 원본 파일은 git 에 없어서 **그대로 남는다.** 되돌릴 저장에 `데이터:` 나 `data/` 가 들어 있으면 **되돌리기 전에**:
1. 되돌린 뒤의 설계에서 빠지는 표·칸을 찾는다 (`git show <그 저장> -- data/model.light.json` 의 바뀐 부분).
2. 그 표·칸에 데이터가 있는지 본다 -- SQLite 는 `data/app.db` 에서 행 수를 세고, Supabase 는 사용자에게 확인을 부탁한다.
   (데이터 검사 장치가 있으면 되돌린 설계는 `verify` 의 "정본에서 빠졌습니다" 에 걸려 **저장이 멈춘다** -- 미리 보는 이유)
3. 데이터가 없으면 그대로 되돌린다. 있으면 사용자에게 보여 주고 고르게 한다:
   ```
   이 저장을 되돌리면 '회비 납부' 표가 설계에서 빠지는데, DB 에 그 표의 기록이 12줄 있어요. 어떻게 할까요?
    1. 그 표는 설계에 남기고 나머지만 되돌리기 (데이터 그대로)
    2. 그 표는 설계 밖에 두기 -- 데이터는 그대로, 검사에서만 빠져요 (정본의 "outside")
    3. 데이터를 data/backup/ 에 복사해 두고 DB 에서도 빼기 (지워져요)
    4. 되돌리지 않기
   ```
   3번은 지워도 된다는 답을 받은 뒤에만, `data/backup/<날짜>-app.db` 로 복사한 다음에 한다. 답은 `DECISIONS.md` 에 그대로.
- 설계가 걸린 되돌리기는 `git revert --no-commit` 바로 다음, 기록을 고치기 **전에** `datalight.py verify data/model.light.json` 을 돌린다 --
  FAIL 이면 `git revert --abort` 로 원래대로 돌리고 위 3단계(사용자에게 고르게 하기)로 간다 (abort 는 그 뒤에 고친 기록도 함께 지운다).
  저장할 때 데이터 검사 장치가 멈춰도 `--no-verify` 로 건너뛰지 않는다 -- 같은 방법으로 간다.
- DB 파일을 지우거나 덮어쓰지 않는다 -- 사용자가 직접, 명확히 요청해도 무엇이 사라지는지 말하고 다시 확인받는다.
- `git stash` 는 `.gitignore` 에 있는 `data/app.db` 를 보관하지 않는다 (DB 는 그대로 있다).

## 3. 되돌린 뒤 (저장은 한 번에)
1. `light-check` 로 사이트가 정상인지 확인한다 (특히 기능 지도의 모든 기능). 설계를 되돌렸으면 데이터 확인(`verify`)으로
   실제 DB 가 설계와 다른지도 본다 -- 다르면 그대로 보고하고 맞출지 묻는다.
2. `FEATURES.md` 와 `NOW.md` 를 되돌린 상태에 맞게 고치고, `DECISIONS.md` 에 왜 되돌렸는지 `[사용자]` 로
   사용자의 말 그대로 한 줄, 흐름 `· 되돌리기 · <기능> · <무엇을> · 완료 · 사용자` 와 그 기능·날짜 파일의 목록·자세히(되돌린 저장·이유)를 남긴다.
   설명서(`manual/`)는 같은 저장에 있었으면 함께 되돌아간다. 사용 방법이 원래대로 돌아왔으면
   `manual/index.html` 의 "바뀐 점"에 되돌린 사실을 한 줄 남긴다 (`light-manual`).
3. 되돌린 변경과 기록을 함께 저장한다 (영어 "Revert ..." 메시지 대신 쉬운 한국어로):
   ```
   git add dev-notes/
   git commit -m "되돌리기: 모양: 기본 색을 파란색으로 -- 원래 색이 더 낫다"
   ```
