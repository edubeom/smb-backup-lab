# 쉬운 풀이 — 사용자가 모르는 말이 나오면

사용자는 개발·데이터를 모를 수 있다. 아래 말이 처음 나오면 **사용자의 일에 빗대어 한두 줄로** 풀고 넘어간다 (이 문서를 그대로 붙여 넣지 않는다).
결정은 Claude 가 하고 이유를 한 줄로 알린다 -- 사용자에게는 **되돌리기 어려운 것**(무엇을 만들지 · 개인정보 · DB 를 만들기·바꾸기·지우기 · 파일 넣기)만 묻는다.

| 말 | 풀이 (예: 반찬가게) |
|---|---|
| 표 · 한 줄 · 칸 | 표는 엑셀 시트 하나, 한 줄은 기록 하나(손님 한 명 · 주문 한 건), 칸은 열(이름 · 전화) |
| 하는 일 | 이 데이터를 쓰는 일 -- "주문 받기", "매출 보기". 누가 · 어느 화면에서 · 어느 표를 만들고 · 읽고 · 고치고 · 지우는지 |
| 다른 표를 가리키는 칸 | 표끼리 잇는 칸 -- 주문의 '손님' 칸은 손님 표의 한 줄을 가리킨다. 손님을 지우려 하면 막을지 · 같이 지울지 · 비울지 정한다 |
| 개인정보 짝 표 | 이름 · 전화 같은 칸은 따로 둔 표(`pi_`)에. 본 줄을 지우면 같이 지워진다 -- 보여 줄 사람을 좁히기 쉽다 |
| 알고 싶은 것 (성공 기준) | 이 데이터로 꼭 나와야 하는 답 -- "손님별 이번 달 주문 금액". 검사가 예시 값으로 실제로 돌려 본다 |
| 예시 값 | 들어갈 법한 **만든 값** 몇 줄 -- 보면 빠진 칸이 잘 보인다. 실제 사람의 이름 · 전화는 쓰지 않는다 |
| 검사 (verify) | 규칙이 나쁜 값(빈 값 · 목록 밖 · 음수 금액 · 중복)을 막는지 직접 넣어 본다. 통과해야 "다 됐다"고 말한다 |
| 되돌릴 수 없는 일 | 데이터가 든 DB 를 바꾸거나 지우기, 파일을 넣기 -- 꼭 사용자에게 묻고, 그 답을 그대로 기록한다 |

보여 줄 것: `build` 가 만드는 **데이터 설명서**(`out/book.html` -- 하는 일 → 화면 → 표 → 예시)와 그림(`view`).
"이 표는 왜 있나 · 누가 쓰나 · 어떤 값이 들어가나"를 설명서로 보여 주고 "맞나요?"라고 묻는다.
